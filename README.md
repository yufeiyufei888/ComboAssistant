# 连招助手

连招助手是一个供个人侧载的 Android 本地触控录制与回放工具。它使用无障碍服务的 `dispatchGesture()` 与可信的 `TYPE_ACCESSIBILITY_OVERLAY`，不需要 Root、Shizuku 或普通悬浮窗权限。

> [!WARNING]
> 当前开发候选为 **v0.2.0-beta.3**。上一版 beta.2 已在 Redmi K80 Pro/澎湃OS 实测确认基本连续录制、保存与回放可用；beta.3 针对安全中心误识别、紧急停止键布局和无障碍服务恢复提示继续完善，但这些新改动仍需重新实机验收，因此继续作为 Beta 提供。请勿用于排位赛、账号资产操作或无人值守自动化，并先确认游戏规则。

## v0.2 重点

- 连续离线录制：3 秒倒计时后透明层持续采集点击、长按、滑动与多指轨迹，直到点击“结束并保存”。两次手势之间的真实等待会写入时间轴，保存后不会自动试播。
- 稳定前台会话：同一游戏内登录页、加载页、Surface 与比赛场景切换会刷新而不是清空悬浮键；输入法、SystemUI 和权限窗口只视为临时遮挡。
- 可选增强识别：用户可单独授权“使用情况访问”。首次连接仅在本次开机范围内重建 Activity 前后台状态，之后每秒增量校验；不保存使用历史，也不联网。关闭或拒绝后继续使用无障碍事件识别。
- HyperOS 实机修复：`com.miui.screenshot` 与 `miui.systemui.plugin` 等已观测系统浮层不能再成为游戏候选或重置稳定计时；输入法和通知栏仍保持安全阻断。
- 安全中心防误绑：`com.miui.securitycenter` 现在按临时系统界面处理，不能成为游戏候选或被保存为连招目标。由于没有可靠的公开 Activity 类名可区分游戏工具箱浮层和真实安全中心页面，本版采用保守门禁：出现该包时暂时隐藏/禁止执行，收到真实游戏事件后再恢复。
- 紧凑悬浮面板：横屏高度限制为约屏幕一半，内容内部滚动，顶部固定“×”；再次点击紫色“连”也可关闭。紫色设置球在正常模式可直接拖动并保存位置。
- 集中布局模式：正常状态下连招键保持锁定。进入“布局按键”后可选择、拖动和调整连招键大小/透明度，也可移动红色紧急停止键并把视觉大小设为 36–72dp；实际触控区始终至少 48dp。默认停止键缩小为 40dp。“完成并锁定”一次保存全部布局，“取消”完整回滚。
- 服务状态恢复提示：主界面区分“未启用”“系统已启用但服务未连接”“服务已连接”，并在等待连接时提供无障碍、自启动和省电策略入口。系统无障碍授权始终由 Android/澎湃OS 管理，应用不能自行授权、强制重启服务或保证划掉后台后继续运行。
- 安全回放：开始前及每个手势段前重新验证目标包名、稳定方向和屏幕状态。回放串行执行；红色停止键会立即停止后续动作并请求系统取消当前手势，若系统拒绝取消，当前手势可能执行到本段结束。

普通无 Root 应用不能在同一透明层上既完整读取原始 `MotionEvent`，又把同一串触摸实时原样透传给游戏。因此录制期间底层游戏不会同步响应；需要根据录制前的画面盲录，保存后再手动回放。这是 Android 公开 API 的能力边界，不等同于小米系统组件的输入层实现。

## beta.3 待实机确认

- 需要在真实游戏中验证 `com.miui.securitycenter` 出现时只短暂安全隐藏，并能在游戏重新产生前台事件后恢复；若澎湃OS不再发送游戏事件，仍可能需要增强识别或手动返回游戏页面触发恢复。
- 需要验证紧急停止键在 36dp/72dp、四角和异形屏安全区域的可达性；系统若拒绝取消已提交的手势，后续动作会停止，但当前手势仍可能执行到本段结束。
- 澎湃OS划掉后台后可能停止无障碍服务进程，甚至要求用户重新检查系统开关。beta.3 改善状态检测与恢复入口，但普通应用不能绕过系统决定或自动重新授权。

## 功能

- 坐标按录制屏幕宽高归一化保存；同方向、不同分辨率按比例映射，方向变化时拒绝执行。
- 每条连招可设置 36–96dp 视觉大小、20%–100% 透明度、单独显示/隐藏、0.25×–4× 倍速、1–999 次重复、0–10 秒固定重复间隔。
- 默认值：56dp、75%、1×、重复 1 次、间隔 100ms。
- 单次录制最多 60 秒或 200 个已完成手势。达到上限自动保存已有有效内容；旋转、熄屏、切换到真实其他应用或服务中断会取消录制。
- Room 保存 v1 版本化 JSON 时间轴，DataStore 保留现有全局悬浮设置；覆盖安装 v0.1 时不做破坏性迁移。
- Debug 版包含触控测试场和仅驻留内存的最近 200 条前台识别日志，不记录窗口文字。

## 使用

1. 安装 Debug APK，阅读用途、误触和游戏规则风险说明后确认。
2. 在系统无障碍设置中开启“连招助手触控服务”。如需增强识别，再在主界面单独开启并授权“使用情况访问”。
3. 打开目标游戏，点击紫色设置球与“新建录制”。倒计时后按预想节奏连续录制；此时游戏不会响应触摸。
4. 点击录制 HUD 的“结束并保存”，命名和编辑参数，然后在自动进入的布局模式中摆放按键，点击“完成并锁定”。
5. 紫色设置球可直接拖动，轻点用于展开/收起面板。正常模式下短按连招键执行、长按编辑；需要移动连招键或紧急停止键时进入“布局按键”。回放中可随时点击红色停止按钮。

## 权限与隐私

应用不声明 `INTERNET`、`QUERY_ALL_PACKAGES` 或 `SYSTEM_ALERT_WINDOW`，不读取窗口内容、截图、账号或游戏数据。无障碍服务保持 `canPerformGestures=true`、`canRetrieveWindowContent=false`、`isAccessibilityTool=false`。

唯一新增权限是可选的 `PACKAGE_USAGE_STATS`；它必须由用户在系统设置中单独授权。应用只查询最近的前台事件用于恢复/校验包名，不持久化结果。

项目不尝试绕过反作弊，也不提供无限循环、定时任务、音量键触发、Root/Shizuku、跨方向执行、云同步或导入导出。

## 构建与验证

环境：JDK 17、Android SDK 36、Gradle 8.11.1；`minSdk 26`、`compileSdk/targetSdk 36`。

```powershell
$env:JAVA_HOME = '<JDK 17 路径>'
$env:ANDROID_SDK_ROOT = '<Android SDK 路径>'
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

本地构建 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。CI 上传的 `ComboAssistant-v0.2.0-beta.3-debug-ci.apk` 使用临时 CI 调试签名，仅用于自动化验证；可侧载候选文件为 `ComboAssistant-v0.2.0-beta.3-debug.apk`，并附带 `SHA256SUMS.txt`。正式发布前仍必须从合并后的 `main` 重新构建并核验包名、版本、权限、文件哈希和既有签名证书。

完整测试、CI 与 Redmi K80 Pro 验收清单见 [docs/testing.md](docs/testing.md)，Beta 状态见 [docs/known-issues.md](docs/known-issues.md)。
